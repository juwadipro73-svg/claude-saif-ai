# Specification: Core Ports & Domain Contracts

## 1. Scope & Objective
This specification establishes the fundamental domain models and abstract contracts that decouple SAIF AI's high-level user interface and workflows from any underlying execution engine, network protocol, or storage mechanism.

---

## 2. Behavioral Domain Models

### 2.1 Chat Conversation & Messages
- **Message Roles**:
  - `User`: Direct input originating from human interaction (typed prompt, transcribed speech, or attached assets).
  - `Assistant`: Responses generated by an AI model, including thoughts, status indicators, and embedded tool requests.
  - `Tool`: The executed results, outputs, or error streams returned from local system actions.
  - `System`: Instructions defining persona rules, capabilities, and system context boundaries.
  - `Summary`: Contextual summarization tokens used to compress extensive conversation histories.
- **Message Attributes**:
  - Unique identification string (UUID-v4 format).
  - Conversation / session grouping token.
  - Textual payload representing markdown body.
  - Optional thinking or reasoning buffer with duration in milliseconds.
  - Associated collection of tool calls initiated during this turn.
  - Streaming status flag to indicate ongoing incremental generation.
  - File attachments collection.
  - Creation timestamp (Unix epoch milliseconds).

### 2.2 Tool Execution Records
- **Tool Categories**:
  - Command Execution (Bash / Shell processes).
  - File Read / Inspection.
  - File Write / Creation.
  - File Modification / Patching.
  - Directory Listing.
  - File Search / Pattern Matching.
  - Web Search & URL Retrieval.
  - Interactive Choice / User Questionnaire.
- **Tool Call Attributes**:
  - Unique call ID.
  - Target operation descriptor name.
  - Executable command or target payload string.
  - Operational status: `PENDING_APPROVAL`, `RUNNING`, `SUCCESS`, `FAILED`, `AWAITING_INPUT`.
  - Captured standard output or error diagnostic text.
  - Process termination exit code (integer).
  - Wall-clock execution duration in milliseconds.

### 2.3 Attachments
- **Attachment Representation**:
  - Unique identifier.
  - File name with extension.
  - Absolute local storage path or content URI.
  - MIME type indicator.
  - Byte size.
  - Media type flags (image, audio, video, document, archive).

## 3. Abstract Service Contracts (Ports)

### 3.1 Agent Backend Port
- Exposes immutable reactive streams for:
  - Current ordered list of conversation messages.
  - Active response streaming flag.
  - Queue of pending tool calls requiring explicit user authorization.
- Methods:
  - `sendMessage(prompt: String, attachments: List<Attachment>)`: Asynchronously dispatches user turn.
  - `approveTool(toolId: String, scope: ApprovalScope)`: Authorizes execution of a pending tool call.
  - `rejectTool(toolId: String, reason: String?)`: Denies execution and communicates refusal back to agent context.
  - `stop()`: Aborts current streaming turn immediately.

### 3.2 Workspace Environment Port
- Exposes:
  - Workspace readiness reactive state.
  - Base directory reference where user project files reside.
- Methods:
  - `ensureReady()`: Verifies directory layout and initial environment setup.
  - `resolvePath(virtualPath: String)`: Maps POSIX virtual paths to actual host file locations safely without directory traversal escapes.
  - `executeCommand(command: String, onLine: (String) -> Unit)`: Executes shell command streaming output lines.

### 3.3 Account Binding Port
- Exposes:
  - Authentication status state.
  - Active user identity descriptor / email.
  - Display name.
- Methods:
  - `checkAuthStatus()`: Validates whether credentials remain valid or need refresh.

### 3.4 Skill Store Port
- Methods:
  - `listSkills()`: Returns collection of stored skills.
  - `findSkill(name: String)`: Retrieves a specific skill document.
  - `saveSkill(skill: SkillItem)`: Persists or updates skill instructions.
  - `deleteSkill(name: String)`: Removes skill from persistent store.

---

## 4. Acceptance Criteria
- Domain models are completely decoupled from any specific transport format (JSON, Protocol Buffers, or WebSocket frames).
- All collections and state fields are strictly immutable; updates must be emitted as new state snapshots.
- Paths resolved through the workspace environment port must strictly reject attempts to access parent directories above the designated root.
